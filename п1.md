1 ситуация) модель waterfall, потому что требования согласованы, есть подробное тз, изменения только по регламенту. плюсы: чёткие сроки и документация. возможные проблемы: сложно вносить изменения, заказчик поздно видит результат.
2 ситуация) модель agile, потому что заказчик не знает итоговый интерфейс, после каждой демонстрации просит правки. плюсы: быстрая обратная связь, лёгкие изменения. возможные проблемы: сложно оценить сроки, проект может разрастись.
3 ситуация) модель инкрементальная, потому что порядок функций известен, каждая часть работает самостоятельно. плюсы: рабочая часть продукта появляется рано. возможные проблемы: сложная интеграция модулей, нужна продуманная архитектура.
4 ситуация) модель итерационная, потому что простая версия, затем анализ ошибок и повторные улучшения, результат заранее неизвестен. плюсы: ошибки находятся рано, точность растёт постепенно. возможные проблемы: без целевой точности улучшать можно бесконечно.
